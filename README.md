# SYPHER Brain

A living, AI-driven 3D visualization of everything that happens in a developer's environment — Claude CLI tool calls, vault edits, shell commands, LLM thoughts — rendered as neurons growing inside an anatomical wireframe brain. Each agent is a real persona with rolling memory, driven by a local Llama-3.2-1B. Each synapse is a real computed embedding similarity. Each visible link in the Obsidian graph is one the brain itself formed.

Runs on a 2016 i7 with no GPU. Total RAM at steady state: **~1.0–1.4 GB**. No telemetry leaves the machine.

## What it is

The SYPHER Brain is a neuromorphic visualization layer for an entire local development environment. Open `http://localhost:5174/` and you see a wireframe human brain spinning slowly in space. As you work — edit a file, run a command, ask Claude something, save a vault note — bipedal agent sprites step out of a hex-grid panel on the left and walk to the brain, each delivering a packet of meaning. Where they arrive, neurons grow. Synapses form between the new neuron and whichever existing neurons it is semantically related to (real cosine similarity from a real transformer). The brain itself pulses on impact. The walker's speech bubble fills in mid-stride with a thought generated by a local LLM in that agent's distinct voice.

Open Obsidian on the same vault. The graph view now contains the same connections the brain formed. They are real wikilinks, written into your `.md` files, persisted on disk.

Everything you see corresponds to something real. Nothing is decorative.

| **llama-server**     | 8090      | Llama-3.2-1B Q4_K_M via llama.cpp, OpenAI-compatible chat API       | ~831 MB|
| **vault-bridge**     | —         | chokidar inotify on SYPHER_VAULT, posts VAULT_NODE per change       | ~30 MB |
| **agent-mind**       | —         | Subscribes to broker, generates AI thoughts per agent, posts back   | ~40 MB |
| **vault-writer**     | —         | Persists brain-formed semantic synapses as real Obsidian wikilinks  | ~25 MB |

## What's real

This list is the load-bearing claim of the project — every item below is computed from actual broker state, not faked.

### 1. The neurons

Every neuron in the brain corresponds to exactly one of:

- **Vault note** (from `SYPHER_VAULT/**/*.md`) — position cached per note id, persists across reloads
- **claude-mem observation** (from `~/.claude-mem/claude-mem.db`) — appended live via 1s tailer
- **Broker feed event** (`NEURAL_FEED`) — every UDP telemetry, every Claude tool call, every ambient pulse, every vault mutation gets one

Positions are sampled inside the anatomical brain mesh by `src/engine/brain-sampler.js` (rejection sampling against the hemisphere + cerebellum + brainstem volumes). **No point leaks outside the wireframe shell.**

Caps: **1,000,000 neurons / 500,000 synapses.** Buffer uploads are partial (only the appended range), not full-buffer rewrites — adding a neuron costs ~200 bytes uploaded, not 32 MB.

### 2. The synapses

Every drawn edge is one of:

- **Base brain wiring** — 16 inter-region anatomical connections + intra-region structural edges, established once at scene init
- **Vault wikilinks** — every `[[link]]` in a `.md` becomes an edge
- **Real `synapticAssociations`** — broker UDP feeds and the ambient pulser ship explicit `{sourceNode, targetNode, weight}` triples; matched against existing neurons by label and rendered with the real weight as activity
- **Semantic neighbors** — every new neuron's label/payload is embedded by bge-small-en. Top-K cosine matches above 0.55 form real edges. Math-true: brightness is the actual computed similarity, no decorative threshold
- **Spatial sector clustering** — new feed neurons connect to their two nearest neighbors in the same sector (real distance computation in 3D, capped K=2)

`_mergeEdges()` deduplicates by endpoint and accumulates. Synapses **never reset** on data refresh.

### 3. The walking sprites

Each broker feed spawns one sprite that walks from its agent's hex card to the brain center.

- **Speed** = `MIN_SPEED + (BASE - MIN) * intensity` where intensity is the broker-reported value (real). Range: 75–180 px/sec.
- **Path** = quadratic bezier with control point biased by `targetSector` — PREFRONTAL feeds arc up, OCCIPITAL drop down, etc. Per-sector geometry, no random drift.
- **Gait** = JS-driven leg and arm transforms. Step phase = `distance_travelled_px / step_length_px`, so legs cycle as fast as the sprite actually moves. Faster walkers step faster. Math-true gait.
- **Footprints** emit per half-stride, perpendicular-offset from heading, alternating left/right. Fade over 1.8s.
- **Direction-aware**: facing flips based on horizontal velocity sign.
- **Speech bubble** starts as `…`, then swaps to an AI-generated thought when `AGENT_THOUGHT` arrives via WS keyed by `feedId`.

### 4. The AI per agent

`agent-mind.js` runs a serial queue against `llama-server`. For each `NEURAL_FEED`:

1. Look up the agent's persona prompt (20 archetypes — `KNOWLEDGE_WEAVER`, `CLAUDE_THINK`, `VAULT_OBSERVER`, etc.)
2. Append the feed to that agent's rolling 8-item memory
3. Build a chat-completion prompt: `system = persona + style constraints`, `user = payload`
4. Call Llama with `max_tokens=18`, `temperature=0.85`, 20s timeout
5. Cache the result by `(agentId, payload)` so identical events don't re-bill the GPU
6. POST `/api/agent-thought {feedId, agentId, thought}` to broker
7. Broker broadcasts `AGENT_THOUGHT` → walker's bubble updates mid-walk

Backpressure: queue capped at 4 entries, oldest dropped; feeds older than 15s skipped.

### 5. The vault is the brain

Every vault-to-vault semantic synapse triggers `vault-writer` to append `[[target]]` to a `## Brain Links` section in the source `.md`. Bidirectional. Debounced (30s per file, batched). Idempotent — never adds a link that already exists.

**Open Obsidian on `SYPHER_VAULT`. The graph view shows the exact same connections the brain formed.** Every wikilink the brain added is a real wikilink Obsidian reads.

### 6. The Claude CLI is the brain

`~/.claude/settings.json` hooks fire `claude-brain-hook.sh` on:

| Claude event       | Brain agent       | Sector         |
|--------------------|-------------------|----------------|
| PreToolUse Read    | `CLAUDE_READER`   | OCCIPITAL      |
| PreToolUse Write   | `CLAUDE_WRITER`   | PREFRONTAL     |
| PreToolUse Edit    | `CLAUDE_WRITER`   | PREFRONTAL     |
| PreToolUse Bash    | `CLAUDE_KERNEL`   | CEREBELLUM     |
| PreToolUse TaskCreate | `CLAUDE_PLANNER` | PREFRONTAL  |
| PreToolUse AskUserQuestion | `CLAUDE_DIALOGUE` | SENSORY_CORTEX |
| PreToolUse Agent   | `CLAUDE_DELEGATOR`| CONCEPT_LAYER  |
| PreToolUse WebFetch| `CLAUDE_BROWSER`  | SENSORY_CORTEX |
| PostToolUse *      | `CLAUDE_RESPONDER`| TEMPORAL       |
| UserPromptSubmit   | `USER_INTENT`     | SENSORY_CORTEX |
| Stop               | `CLAUDE_CYCLE`    | TEMPORAL       |

Additionally, `transcript-watcher` tails `~/.claude/projects/**/*.jsonl` and extracts:

| Block type             | Brain agent     | Sector      |
|------------------------|-----------------|-------------|
| `thinking`             | `CLAUDE_THINK`  | HIPPOCAMPUS |
| `text` (assistant)     | `CLAUDE_VOICE`  | PREFRONTAL  |
| `tool_result` (user)   | `TOOL_FEEDBACK` | OCCIPITAL   |

Every decision Claude makes, every line of code it writes, every thought block — flows through `:3456` UDP or `:9800` HTTP into the brain. Click `CLAUDE_WRITER`'s neuron to see exactly what was edited. The brain becomes Claude's externalized cognition in real time.

### 7. The real classifier (no regex)

Two places that used to be regex / dir-rules are now real transformer inferences:

- **Broker command classifier** (`dissectCommandContext`): embeds the command via bge-small-en, cosine-matches against 10 sector anchor texts, picks top-1. Regex kept only as cold-start fallback.
- **Vault note classifier** (`classifyNote`): embeds `label + subtitle + dir` and matches against 6 category anchors. Dir-rules retained as fallback.

`BgeClassifier` in `bge-classify.js` is shared between them — anchors embedded once at startup, queries cached LRU.

## Performance — does it slow down the laptop?

Designed for a **2016 quad-core i7 with 7.6 GB RAM, no NVIDIA GPU**.

| State              | Total RAM | CPU (4 cores)    | Notes |
|--------------------|-----------|------------------|-------|
| Steady idle        | ~1.0 GB   | 0.5–2 %          | Ambient broker pulses every 2–5s |
| Active AI thought  | ~1.4 GB   | 40–50 % (1 core) | Llama generating ~9 tokens, ~1.5 s |
| Vault edit burst   | +0.1 GB transient | 15 % (1 core)| Embedding + classification |
| First page load    | +0.5 GB browser | 30 % (2 cores)| Vite serves first bundle |
| Worst case         | ~2.0 GB   | 60 % (2 cores)   | Multiple AI thoughts queued + heavy browser |

**Why it stays light:**

- Llama runs with `--no-repack` (skips weight repacking, saves ~450 MB)
- llama-server `-t 3` leaves one core free for the browser
- `--cache-ram 64` gives Llama a 64 MB prompt cache (massive speedup on repeated system prompts)
- agent-mind has a serial queue + backpressure — never more than one Llama inference in flight, never more than 4 pending
- Per-(agent, payload) thought cache means repeated work is free (0 ms)
- embed-server is **threaded** (parallel HTTP) but ONNX inference is **locked** (serialized) — clients don't block each other for socket time
- Partial buffer uploads — appending a neuron is ~200 bytes, not 32 MB
- Edge dedup by endpoint hash — synapses are never duplicated
- The vault watcher uses inotify (zero polling); the claude-mem tailer polls 1/s at ~1 KB/req

If your machine is more constrained you can:

- Drop the Llama context: `-c 512` instead of `1024` (save ~16 MB)
- Reduce `MAX_VECTORS` in `vector-memory.js` (default 4000)
- Set `MAX_FEED_NEURONS` lower than 999k

## Install

```bash
# 1. Clone
git clone https://github.com/ydngemini/sypher-brain.git
cd sypher-brain

# 2. Node deps
npm install

# 3. Python env for the embed server (bge-small-en ONNX + UMAP)
python3 -m venv .venv
.venv/bin/pip install onnxruntime tokenizers numpy umap-learn scikit-learn

# 4. Place the bge-small-en model where embed-server.py expects it
#    Default path: YDNIDE/.sypher/models/models--qdrant--bge-small-en-v1.5-onnx-q
#    Override with $MODEL_DIR if you have it elsewhere
#    Download from: https://huggingface.co/qdrant/bge-small-en-v1.5-onnx-q

# 5. Build llama.cpp (CPU)
cd ../llama.cpp   # or wherever you have it
cmake -B build -DGGML_NATIVE=ON -DLLAMA_CURL=OFF
cmake --build build --config Release -j 3 --target llama-server

# 6. Grab Llama-3.2-1B-Instruct Q4_K_M (~770 MB)
mkdir -p /your/models/dir
curl -L -o /your/models/dir/Llama-3.2-1B-Instruct-Q4_K_M.gguf \
  https://huggingface.co/bartowski/Llama-3.2-1B-Instruct-GGUF/resolve/main/Llama-3.2-1B-Instruct-Q4_K_M.gguf

# 7. Configure paths in start.sh
#    LLAMA_BIN and LLAMA_MODEL at the top of the script

# 8. Run
./start.sh
```

Then open `http://localhost:5174`.

For Claude CLI hooks to fire, add the snippet from `hooks/claude-brain-hook.sh`'s docblock to `~/.claude/settings.json`. The script reads JSON from stdin and POSTs to `:9800/api/feed` — fire-and-forget with a 1s timeout so it never blocks Claude.

For boot persistence:
```bash
systemctl --user enable sypher-brain.service
systemctl --user start sypher-brain.service
```

## Conventions

- **No telemetry leaves the machine.** All inference is local — Llama via llama.cpp, embeddings via ONNX. No Anthropic / OpenAI / cloud calls anywhere in the runtime.
- **Math-true rendering.** Synapse brightness equals computed similarity. No decorative thresholds. If math says weight ≈ 0, the edge is drawn at brightness ≈ 0 (invisible) rather than removed.
- **Real per agent.** Every walking sprite, every thought, every neuron position is anchored to a real event. The brain is a faithful projection of the user's actual activity, not a decoration.
- **Synapses are permanent.** Once a connection forms, it stays. Eviction is FIFO at the cap (1600 persisted, 500k buffer), never wiped.
- **Cycle-safe vault writes.** vault-writer's edits trigger vault-bridge re-reads, but the new `[[wikilink]]` is just a structural extension — same node id, same cached position, no retrigger of the semantic synapse that produced it.

## Known constraints

- **CPU only.** The 2016 i7 has no NVIDIA. Llama and bge both run on CPU. If you have a GPU, set `-ngl` in `start.sh`.
- **Cold start ~15s.** Llama loads its weights (~5s), bge loads its ONNX session (~3s), broker waits for embed-server before loading sector anchors (~3s).
- **First Llama inference ~4s.** Subsequent (with prompt cache hot) ~0.5–1.5s.
- **Vector memory has a 4000-vector cap.** Old vectors evict FIFO. For longer-horizon semantic recall, increase `MAX_VECTORS` in `vector-memory.js` (each vector is 1.5 KB).
